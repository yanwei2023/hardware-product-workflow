# 局域网安装与产品开发模拟测试指南设计

## 1. 目标

生成一份面向首次内部试点人员的独立中文指南，使用户无需理解代码结构，也能：

1. 在一台公司局域网主机上安装并启动当前验证分支；
2. 从其他电脑通过浏览器访问同一套系统；
3. 按角色模拟一个简单的新产品开发项目；
4. 验证 S0、Agent 执行、人工审核、S0 Gate、项目蓝图和 S1 自动派工；
5. 记录测试结果，并在异常时保留数据和诊断证据。

最终交付文件：

```text
局域网安装与产品开发模拟测试指南.md
```

## 2. 部署方式

采用一台主机、多个浏览器客户端的 Node.js 直接安装方案。

- 主机负责 Git 仓库、Node.js 运行环境、服务进程和 JSON 数据文件。
- 参与者电脑不安装项目，只需与主机处于同一局域网并使用现代浏览器。
- 服务使用 `HOST=0.0.0.0` 监听，并启用试点访问码。
- 默认使用当前已验证分支 `codex/agent-driven-lifecycle`。
- 第一次启动前必须运行 `npm run pilot:check`。
- PostgreSQL 非严格预检缺少 `DATABASE_URL` 或 `psql` 时，明确区分为可选环境提示，不误报为 JSON 局域网试点失败。

## 3. 指南结构

指南按实际操作顺序编写：

1. 当前版本适用范围和已知边界；
2. 主机与客户端准备清单；
3. GitHub 克隆、分支切换和依赖安装；
4. 完整试点门禁检查；
5. 设置访问码并启动局域网服务；
6. 获取推荐访问地址并验证诊断端点；
7. 客户端连接和角色分配；
8. 简单产品项目模拟；
9. 每一步的预期系统状态；
10. 测试记录表、问题分级和证据要求；
11. 检查点、备份、停止服务和恢复；
12. 常见故障排查。

命令同时提供 macOS/Linux `zsh`/`bash` 写法。Windows 客户端只使用浏览器；本轮不把 Windows 作为服务主机。

## 4. 模拟项目

使用虚构项目“便携式温湿度记录仪”，仅作为本次操作示例，不写入平台模板或默认数据。

建议立项输入：

- 项目类型：全新产品开发；
- 目标市场：实验室、仓储和小型工业现场；
- 客户场景：连续记录环境温湿度，支持现场查看和导出；
- 产品能力：电子硬件、嵌入式固件、结构与工业设计、测量与信号链、实体产品验证；
- 技术范围：传感器、采集电路、低功耗固件、显示与存储、便携外壳；
- 合规要求：目标市场电气安全、EMC、环保和计量适用性评估；
- 供应方式：核心设计自研，PCB 和结构件外协；
- 交付模式：标准产品销售，提供说明书和基础售后；
- 运营要求：校准建议、固件维护、客户问题处理；
- 风险等级：中。

指南不预先替 Agent 编造正式研究结论；这些内容仅用于模拟立项定义和流程行为。

## 5. 角色和操作脚本

建议至少使用三个浏览器会话或三台电脑：

- 项目经理：创建候选、保存立项定义、批准 S0 Gate、批准项目蓝图；
- 研发负责人：审核技术类 S0 Agent 交付物；
- 质量负责人：审核质量/合规类交付物，并观察阶段门阻塞。

操作必须覆盖：

1. 创建候选后只有 S0，且出现 10 个 Agent 队列任务；
2. 立项定义保存后生成项目绑定的蓝图预览；
3. 处理 S0 Agent 队列；
4. 至少对一个交付物执行“要求修改”，确认 Agent 自动重新排队，再处理并批准；
5. 批准其余必需 S0 交付物；
6. S0 Gate 从 BLOCKED 变为 READY；
7. 项目经理批准 S0 Gate，确认立项基线被冻结；
8. 处理项目蓝图 Agent 任务；
9. 项目负责人批准蓝图；
10. 确认总阶段数为 11（S0 加 S1-S10）、当前阶段为 S1，并出现 S1 Agent 队列任务；
11. 检查待办、通知和审计记录。

## 6. 验收标准

局域网模拟测试通过需同时满足：

- 主机 `/health` 返回 200 和 `ok: true`；
- 主机 `/ready` 返回 200 和 `ready: true`；
- `/runtime/network` 显示 LAN 模式并给出可访问的局域网 URL；
- 未提供访问码时，受保护的数据接口返回 401；
- 至少一台其他电脑能打开 React 工作台并使用访问码加载项目；
- 新项目创建后只有 S0；
- Agent 退回重做和人工批准链路可用；
- 未批准项目蓝图前不存在正式 S1-S10；
- 蓝图批准后一次性生成 S1-S10，并自动派发 S1 Agent 工作；
- 审计记录能够对应关键操作；
- 试点前检查点和测试结果记录已保存。

## 7. 当前边界

指南必须明确：

- 当前适合局域网流程模拟，不等同于生产部署；
- 外部大模型尚未接入，Agent 输出为受控的确定性模板模拟；
- 默认使用 JSON store，不是完整 PostgreSQL 在线 repository；
- 试点访问码不替代正式登录和 SSO；
- 单份文档等级手动调整、条件适用 N/A 和降级例外审批尚未形成完整操作闭环；
- 多人高并发冲突、TLS、反向代理、生产备份与灾备不在本次验收范围。

## 8. 输出质量要求

- 所有命令可直接复制，变量使用安全的示例值；
- 明确哪些命令在主机执行，哪些操作在客户端执行；
- 每个关键步骤包含“操作、预期结果、异常处理”；
- 不要求用户先自行拉取代码后再让 Codex继续；
- 不把示例产品写成平台默认产品；
- 不声称未实现能力已经完成；
- 指南本身加入 Git 并同步到 `codex/agent-driven-lifecycle`。
